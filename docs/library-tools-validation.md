База `25b701b`, ветка `reed/library-tools`. Первый этап и его три review описаны отдельно в [validation.md](validation.md). Этот документ относится только к новым возможностям.

- SwiftCore после исправлений review: 60 тестов в итоговом отчёте Swift Testing, opt-in benchmark запускался отдельно. Реальная SQLite, миграция одиночного фото, черновики, атомарная публикация, метаданные, перенос, история и планировщик.
- Backend: typecheck, 13 тестов (включая PostgreSQL без пропусков), JS build. Проверены HTTP/OTP, неизменный UUID при смене телефона и восстановлении, перезапуск dev identity store, блокировка удаления и повтор worker.
- Xcode 26.6: generic iOS Simulator `build-for-testing` для приложения и test bundles. Incremental-сборка при изменении публичных Swift API подхватывала устаревший модуль; итоговая `clean build-for-testing` в `.local/VerificationData` прошла. Проверен итоговый Info.plist: background identifier, fetch, версия и API URL.
- `git diff --check`; Xcode-проект сгенерирован из `ios/project.yml`.

## Границы проверки

Новые UI-сценарии и тест crop-геометрии **скомпилированы, но не исполнены**. На Mac нет установленного Simulator runtime, переустановок и загрузок runtime не делали. Пользователь остановил новые push, поэтому GitHub CI для этих коммитов не запускался. Снимки первого этапа не считаются проверкой новых экранов.

На устройстве ещё нужны: камера/PhotosPicker с несколькими фото, выделение и повторный OCR, share/fileImporter, Dynamic Type/VoiceOver, фоновые запуски, уведомления при закрытом приложении. iOS может не предоставлять фоновое время; уже подготовленная очередь ограничена семью днями.

Реальные SMS/SMTP, secure email change Supabase, административное удаление identity и TestFlight не включались. Для восстановления нужен заранее подтверждённый email; без него обхода входа нет. Backup переносит библиотеку в пустое хранилище, не смешивает две коллекции; файл не зашифрован. Облачная синхронизация не реализована.

## Независимый review

Один `architecture_researcher` на Astra High выполнил независимый read-only review после реализации (`25b701b..44d2ad9`). Найдены и исправлены три P2:

1. «Сохранять фото» удалял вложения восстановленного черновика. Теперь меняет только preference для следующих добавлений; явное удаление остаётся отдельной командой. Добавлен platform-регрессионный тест удержания фото, следующего добавления без фото и удаления без потери текста.
2. Управление авторами не обновляло `authorNames` черновика нового источника, позволяя создать прежнее имя заново. Rename/merge/remove теперь преобразуют список с нормализацией и dedupe. Три варианта проверены через восстановление черновика и его публикацию в SQLite.
3. Повтор удаления после сетевого сбоя использовал истёкший access token. `AccountDeletionService` обновляет credentials, проверяет UUID и сохраняет фазу/rotated refresh token до повторного DELETE. Core-тесты покрывают повторный timeout, успешный retry и отказ при чужом UUID.

Также исправлено завершение локальной очистки при отсутствующей API-конфигурации; фаза `.accepted` завершается без сети. Тот же reviewer проверил только исправления и подтвердил закрытие всех трёх замечаний, новых дефектов в них не обнаружил. Дополнительные агенты для реализации не использовались.

Полный SwiftCore-набор после правок зелёный, backend после последнего своего изменения — 13/13, iOS `clean build-for-testing` зелёный. Platform-регрессионные тесты также только скомпилированы, не исполнялись. Backend после review не менялся; успешную неизменённую проверку повторно не запускали.
