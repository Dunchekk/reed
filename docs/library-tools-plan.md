# Второй этап: повседневная библиотека

База: `25b701b`. Реализация разрешена. По уточнению пользователя новые push и merge
приостановлены: первые пять коммитов уже в GitHub, остальные остаются локально.
Ориентир — 11 коммитов, один независимый reviewer после реализации.
Реальные SMS/почта, production, TestFlight и облачный архив не подключаются.

## Границы и решения

- SwiftUI отображает состояние и передаёт команды. Составление карточки,
  автосохранение, работа с вложениями, перенос и управление справочниками —
  отдельные сценарии/порты ReedApplication. SQLite и файлы — ReedPersistence.
- У карточки упорядоченный список вложений. Старое одиночное фото мигрирует
  без потери. Удаление вложения не меняет текст. «Сохранять фото» относится
  к следующим снимкам, по умолчанию включено и запоминается для аккаунта; выключение
  не удаляет уже прикреплённые фото, включая фото в восстановленных черновиках. OCR доступен в обоих режимах.
- Черновики изолированы по аккаунту, включают поля и сохранённые вложения.
  Автосохранение последовательное; публикация карточки и удаление черновика
  атомарны. Несохранённые изменения существующей карточки также восстанавливаются.
  Главная показывает небольшую ссылку с количеством; список поддерживает свайп.
- Управление библиотекой открывается из Архива: четыре раздела, поиск, число
  связанных карточек, переименование, объединение в выбранную сущность и удаление
  связи без удаления карточек. Подтверждение показывает последствия. Изменения
  обновляют поиск, правила и версии; старый редактор не возвращает старые названия.
- Резервная копия имеет версию формата и контроль целостности фото. Секреты входа
  не экспортируются. Восстановление — в пустую библиотеку с предварительным
  просмотром; повтор того же импорта не создаёт дубликатов. Объединение двух
  непустых архивов не маскируется под восстановление. Ошибка не оставляет половину БД.
- Настройки: «Добавление», «Данные», «Аккаунт». Очистка локальных данных и удаление
  аккаунта разделены, отменяют уведомления и требуют явного подтверждения в UI.
- Восстановление доступа — код на заранее подтверждённую резервную почту.
  Смена телефона сохраняет UUID аккаунта и требует подтверждения нового номера.
  Нельзя восстановить аккаунт без доказательства владения. Адаптер провайдера
  заменяемый; dev-провайдер ограничен синтетическими адресами/номерами.
- Фоновое продление — best effort iOS, без обещания точного запуска. Ускорение
  планировщика сохраняет правила полного пула, паузу, квоту и стабильность времени.

## Последовательность коммитов

1. План, контракты и границы этапа.
2. Несколько вложений, миграция и настройки добавления.
3. Хранилище черновиков и сценарий редактора вне UI.
4. Фото/OCR, восстановление черновиков, список и плашка Главной.
5. Управление источниками/авторами/папками/тегами из Архива.
6. Экспорт, проверка, восстановление и локальная очистка в Настройках.
7. Возвращения: измеряемое ускорение, фоновое продление и действия карточки.
8. Backend: смена номера, резервная почта, восстановление и удаление аккаунта.
9. Экраны аккаунта и обновление сохранённой сессии без смены библиотеки.
10. Сквозные проверки, русские README, актуальный Xcode-проект и CI.
11. Подтверждённые исправления независимого review и итог проверки.

Тесты сопровождают поведение: миграции, несколько фото, выход/перезапуск редактора,
атомарная публикация, конфликт старого редактора, объединение справочников,
повреждённый/повторный импорт, неизменность выбора планировщика и изоляция аккаунта.
UI-сценарий подготовлен для GitHub Simulator, но в этом этапе не запускается:
пользователь остановил отправку новых коммитов. Локально нет Simulator runtime;
доступна компиляция приложения и test bundles. Физический iPhone не подменяется CI.
