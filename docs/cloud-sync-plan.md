# Облако и второй iPhone

База `c23a8d4`, новая ветка `reed/cloud-sync`. Все коммиты локальные: никаких push, PR или merge. Основная реализация одним агентом; один независимый Astra High reviewer после завершения и исправления подтверждённых замечаний. Ориентир — 30 осмысленных коммитов.

## Решения и границы

Figma `4TxAyioeWNLLl9e0FOeqOb`, экран `383:8972` «Данные и синхронизация»: тумблер, статистика, время последнего обмена, ручной запуск, auto/Wi-Fi, данные и отдельная опасная зона. Сохраняем текущие SF, цвета, отступы и радиусы. Фиктивные числа из макета не используем. Состояния переноса/конфликтов/устройств расширяют этот экран.

Старое предложение read-only cache в спецификации заменяем полной локальной репликой: архив, поиск, создание и редактирование работают офлайн. SQLite остаётся рабочей базой клиента; PostgreSQL хранит подтверждённые версии, историю изменений и принадлежность аккаунту. UI не выбирает победителя конфликта и не управляет сетевыми протоколами.

- Канонические типизированные записи отдельно для карточек, источников, авторов, папок, тегов и настроек возвращений. Поля метаданных не копируются в облачные карточки. UUID сохраняются; серверные версии отличаются от локального optimistic version.
- Локальные изменения и отметки отправки записываются одной SQLite-транзакцией. Outbox имеет стабильный operation ID, base version, immutable payload, generation локального изменения. Повтор после потерянного ответа идемпотентен; подтверждение не стирает следующую правку.
- Серверные записи имеют порядок изменений внутри аккаунта и epoch библиотеки. Пагинация и cursor не пропускают параллельные записи. Удаление облака меняет epoch, старые устройства останавливаются вместо повторной загрузки удалённого архива.
- Конфликты сохраняют обе версии. Выбор: принять облачную, сохранить свою поверх текущей версии, для карточки — оставить обе. Удаление не воскресает от старого устройства; восстановление из корзины и постоянное удаление различаются.
- Фото неизменяемы: оригинал и превью, размер и SHA-256. Части загружаются с offset/повторами; после перезапуска обмен продолжается. Сервер не публикует незавершённые фото. Клиент не заменяет проверенный файл повреждённым ответом.
- Включение явно объединяет библиотеки по UUID; до старта показывает локальные/облачные количества и объясняет конфликты. Переход не удаляет локальные данные. Отключение на одном iPhone сначала завершает обмен и проверяет полноту локальных фото; облако других устройств остаётся.
- Черновики и предпочтение «Сохранять фото» остаются на устройстве. Существующая история открытий переносится за последние 90 дней. Выключение истории сохраняет прежний контракт: прекращает сбор и использование в подборе; уже собранные события удаляются отдельной очисткой или по сроку. Техническая история возвращений нужна для общей паузы. Настройки разрешений iOS и транспорта локальны.
- В облаке выбор карточек и план принадлежат серверу. Доставка на один явно выбранный iPhone; локальная очередь облачной реплики выключена. APNs изолирован адаптером, production-сертификаты/ключи не устанавливаются. Без APNs-конфигурации экран честно показывает отсутствие доставки; план и синхронизация доступны.
- Backend использует существующий PostgreSQL и приватный файловый ObjectStore для локальной разработки; интерфейс позволяет заменить его внешним объектным хранилищем. Никакого публичного bucket. Реальных SMS, SMTP, deployment и TestFlight нет.
