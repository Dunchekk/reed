# Контракт локального архива

Запрос включает быстрый поиск, keywords, теги (любой), автора, источник, папку,
избранное, период сохранения и область active/hidden/trash. Группы соединяются
через И. Нижняя граница периода включительна, верхняя исключительна; UI передаёт
начало следующего дня для выбранной конечной даты.

Поиск использует текст, заголовок, комментарий, название источника и авторов.
Строки нормализуются в Unicode NFC, нижний регистр, ё→е. Пунктуация разделяет
слова; все токены должны присутствовать как начало слова. Стемминга, произвольных
подстрок, пользовательских FTS-операторов и семантического поиска нет. Search и
keywords объединяются в один набор токенов через И. Пустой набор не ограничивает
выборку. Примеры: `fixtures/archive-search.json`.

Ограничения запроса: страница 1–100 записей, до 100 ID тегов, 64 токена и 8192
UTF-8 байт в поиске. Это техническая защита запроса, а не ограничение текста карточки.

Порядок: createdAt+ID для новых/старых, нормализованный заголовок или начало текста
+ID для алфавита, сохранённый shuffle key со стабильным seed+ID для случайного.
Cursor непрозрачный; привязан к точному запросу и revision библиотеки. После
изменения библиотеки старый cursor отклоняется, UI начинает выборку заново.
Таким образом страницы не смешивают старое и новое состояние архива.

Выдача содержит только краткую проекцию и следующий cursor. Полный текст и фото
запрашиваются при открытии карточки. Будущий PostgreSQL-адаптер обязан пройти те же
примеры; встроенный русский стеммер нельзя включать без изменения контракта.
