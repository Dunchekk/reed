# Cloud protocol v1

HTTPS/Bearer в production, локальный HTTP только в Debug. Account ID берётся из подтверждённой identity, не из request body. Все идентификаторы/версии/cursors привязаны к аккаунту и epoch. JSON даты — ISO8601 UTC, сервер канонизирует UUID в lowercase (ввод нечувствителен к регистру). Числа версий/cursor — безопасные целые до 2^53−1.

Запись: `{kind,id,version,sequence,payload}`; `payload:null` — постоянная tombstone. Типизированный payload карточки содержит ID связей и вложений, не копии общих сущностей. Удалённая в корзину карточка ещё имеет payload и `deletedAt`. Постоянная tombstone не перезаписывается обычным upsert.

Mutation: `{operationID,kind,id,baseVersion,payload}`. Сервер сохраняет fingerprint и результат под operationID в той же транзакции. Повтор идентичного запроса возвращает прежний результат; тот же ID с другим запросом отвергается. Несовпадающая версия возвращает текущую запись как конфликт. Клиент сохраняет неизменяемую попытку до подтверждения; новый локальный edit имеет новую generation.

Pull: epoch + `after` (sequence), limit и верхняя граница страницы. Sequence назначается под блокировкой состояния библиотеки аккаунта, поэтому порядок commit совпадает с порядком sequence. Сохраняется полная журналируемая запись изменения; пагинация не зависит от перезаписи актуальной строки. Epoch mismatch прекращает автообмен, не включает новую загрузку самостоятельно.

Первое включение: preview → явное объединение по UUID → загрузка/скачивание с сохранённым прогрессом → cloud. Отключение: синхронизация → нет конфликтов/неотправленных правок → проверенная локальная копия фото → local. Сброс облака отдельный: epoch меняется, подтверждения старых операций больше не действуют.

Медиа: UUID вложения + original/thumbnail manifest `{size,sha256}`. Upload session хранит offset, фиксированный manifest и срок; чанки ограничены. Повтор уже записанного диапазона должен совпадать. Завершение проверяет длину и hash; только после него вложение доступно карточкам и authenticated download. URLs/пути от клиента не принимаются.

Архитектура: ReedDomain — переносимые модели и инварианты; ReedApplication — engine/порты; ReedPersistence — атомарная SQLite интеграция; Platform — HTTP/файлы/сеть/APNs; SwiftUI — отображение состояний и команды. Backend разделяет contracts, repository, media, return-domain, delivery и routes.

Отключение имеет сохранённый промежуточный режим `leaving`: после проверки полноты и атомарного снятия репликации новые локальные правки больше не отправляются. Повторяется только отзыв устройства, затем включается локальная очередь уведомлений. Сбой ответа не заставляет повторно загружать библиотеку. После чужого сброса `revoked` требует явного выбора: повторное объединение или полная локальная копия. Недостающие фото того же epoch можно скачать после явного повторного присоединения.

История открытий хранится до 90 дней. Перенос существующих событий не создаёт новых открытий; выключенная история не собирается и не влияет на подбор, но не означает очистку прежних событий. Отдельная очистка создаёт tombstones. Это сохраняет поведение локального режима.
