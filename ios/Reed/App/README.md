# Сборка приложения и жизненный цикл

`ReedApp` создаёт клиент входа и Keychain store. `LibraryHostView` открывает
библиотеку только для подтверждённого UUID аккаунта. Каждый аккаунт получает
отдельную SQLite и каталог фотографий; выход сохраняет данные, но закрывает UI.

`LibraryContext` — место сборки зависимостей. Экраны получают протоколы, а не
DatabasePool. `ReturnCoordinator` связывает локальный план с очередью iOS:
отменяет устаревшую работу, показывает ошибки и фактический горизонт очереди.
`RootView` отвечает за четыре вкладки и переход из уведомления с проверкой аккаунта.

План пересчитывается при запуске, возврате в foreground, значимом изменении
системного времени и правке карточек/правил. Просмотр Главной читает сохранённый
результат. При выходе сначала останавливаются незавершённые добавления и очищается
очередь, затем очищается вход. Старый async-ответ не должен снова открыть аккаунт
или поставить уведомления после выхода.

На старте удаляются карточки, проведшие в корзине семь дней, и файлы без ссылок.
Очистка файлов выполняется до открытия редакторов, чтобы не удалить ещё не
зафиксированное вложение. В foreground повторяется очистка строк корзины и истории;
оставшиеся файлы будут убраны при следующем открытии библиотеки.

Фоновый пересчёт через BGTaskScheduler пока не подключён. Уже поставленные
уведомления не требуют работающего приложения. Новые карточки после исчерпания
локального горизонта появятся после открытия Reed; интерфейс сообщает этот предел.
