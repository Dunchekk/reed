# Облако в интерфейсе

Основа экрана — Figma «Данные и синхронизация», узел `383:8972`: чёрный фон, панели #191919/#262626, радиус 4, отступ 16, зелёные системные переключатели, кнопка высотой от 44. Шрифт — системный San Francisco; основной текст 16, подписи 14/12, заголовок 24 с поддержкой системного масштаба.

`CloudSettingsModel` хранит состояние экрана и вызывает порты. Он не выбирает версию конфликта автоматически, не пишет SQL и не отправляет фотографии самостоятельно. Порядок обмена и переходов принадлежит `CloudSyncEngine` в ReedApplication; composition root находится в App/CloudRuntime.

Статистика различает количество карточек на устройстве, подтверждённые записи, очередь изменений и число карточек в облаке. Равные количества сами по себе не означают завершённую синхронизацию. Отсутствие связи не заменяется фиктивными данными; неподключённая доставка уведомлений указана до включения облака.

Первое включение показывает обе библиотеки и требует подтверждения объединения. Отключение сохраняет полную локальную копию. Черновики остаются локальными; резервные копии доступны через отдельный экран данных.

Конфликты показываются двумя версиями с текстом, метаданными, фото и человекочитаемыми правилами. Ссылка на удалённую карточку не заменяется техническим UUID. Детальный экран сохраняет идентификатор показанного конфликта: если данные изменились после открытия, repository отклоняет устаревший выбор. Копирование создаёт новый UUID карточки и не отменяет серверную tombstone.

Экран устройств отдельно выбирает единственного получателя уведомлений. Отключение текущего iPhone использует сценарий полной локальной копии; для другого устройства сохраняется отзыв регистрации. Удаление облака меняет epoch и не удаляет локальные библиотеки. Состояние revoked не возобновляет обмен само: пользователь явно выбирает повторное объединение или локальный режим.
