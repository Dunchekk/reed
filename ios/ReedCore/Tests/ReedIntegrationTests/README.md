# Сквозные тесты облака

Два настоящих клиента Swift: отдельные SQLite, файлы фото, device identity, HTTPCloudClient и CloudSyncEngine. Backend работает на loopback HTTP и тестовом PostgreSQL; APNs и внешняя авторизация не используются.

Удобный запуск из корня: `TEST_DATABASE_URL=... scripts/cloud-e2e.sh`. Скрипт управляет временем жизни тестового сервера и сохраняет диагностический лог в `.local`.

Без `REED_CLOUD_E2E_CONFIG` тест пропускается. Сначала запустите `server/test/support/cloud-e2e-server.ts` с `TEST_DATABASE_URL` и `REED_CLOUD_E2E_CONFIG`, указывающим на игнорируемый локальный JSON. Затем с тем же путём выполните `swift test --filter twoSwiftReplicas`. Сервер пишет временный синтетический токен с правами 0600; SIGINT/SIGTERM останавливает сервер, удаляет тестовый аккаунт, фото и JSON.

Сценарий проверяет потерянный ответ после подтверждения сервером, продолжение из outbox, фото больше одного чанка, две офлайн-правки, сохранение обеих версий, запрет воскрешения удалённого UUID и остановку второго клиента после сброса epoch. Это исполняемый интеграционный тест на Mac; он не проверяет UI и APNs на iPhone.
