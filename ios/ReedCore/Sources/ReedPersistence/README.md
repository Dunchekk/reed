# Локальное хранение

`LibraryDatabase` открывает DatabasePool в каталоге UUID аккаунта. Foreign keys
включены, миграции версионированы. Не удаляем пользовательскую БД при ошибке схемы.
Новая схема оформляется новой миграцией после публикации версии приложения.

- `LocalLibraryRepository`: карточки и связи в транзакции, optimistic version,
  metadata-каталог, корзина. Общие изменения источника/автора обновляют связанные
  поисковые документы; неизменённые метаданные не вызывают полную переиндексацию.
- `ArchiveQueries`: FTS5, prefix-поиск, нормализация регистра и е/ё, keyset cursor.
  Cursor связан с фильтром и ревизией библиотеки. Случайный порядок имеет seed.
- `FileAttachmentStore`: UUID-пути, atomic write оригинала и миниатюры, orphan GC.
- `LocalActivityRepository`: 90 дней открытий, отдельные manual/notification;
  выключение прекращает запись и использование, очистка — отдельное действие.
- `LocalFeedRepository`: ограниченные проекции объяснимых групп без hidden/trash.
- `LocalReturnRepository`/`ReturnPlanning`/`ReturnCandidates`: настройки, FTS-флаги,
  metadata всего допустимого архива, seed дня, решения и техническая история.

Пересчёт плана — одна SQLite-транзакция. Прошедшие слоты сохраняются; уже занятая
дневная квота не сбрасывается правкой окна. Будущее отменяется и заменяется,
неизменённые назначения сохраняют ревизию. Повторное открытие приложения не
накапливает квоту охвата заново. История открытий и техническая история раздельны.

Фотографии не лежат в БД. `card_attachments` хранит упорядоченные UUID вложений; списки получают
короткое текстовое превью. Очистка orphan-файлов выполняется до начала редактирования.


- `LocalDraftRepository`: неполные данные редактора, ссылки на фото, атомарная публикация; tombstone запрещает запоздалое автосохранение после закрытия черновика.
- `LocalCatalogManagementRepository`: переименование, объединение и удаление связей с проверкой ревизии; обновляет версии карточек, FTS, правила и черновики в той же транзакции. Обычный save карточки не меняет общие названия.
- `LocalLibraryBackupRepository` + `FileBackupArchive`: согласованный снимок БД и потоковый архив `.reedbackup` с SHA-256 описания и каждого файла. Перед восстановлением проверяются формат, размеры, ссылки и диапазоны. Медиа получают новые UUID; транзакция восстанавливает только пустую библиотеку. Повторный импорт того же ID не создаёт дублей.

Архив не зашифрован и не содержит токенов входа/телефона аккаунта. Восстановление не объединяет две библиотеки. При очистке остаются только технические tombstone черновиков без их содержимого; после восстановления старые callbacks также не оживляют закрытые черновики.
