# SQLite-реплика облака

Триггеры помечают изменения карточек, связей и правил в той же транзакции, что и основная запись. `cloud_dirty` хранит generation; `cloud_outbox` фиксирует неизменяемую попытку с operation ID и base version. Подтверждение очищает только отправленную generation, поэтому следующая офлайн-правка сохраняется.

`cloud_shadow` содержит актуальную подтверждённую версию. Входящая страница, cursor и проекции обновляются атомарно. Зависимости из следующих страниц ждут в `cloud_projection`; локально изменённые документы сохраняются как конфликты. Проекции обновляют обычные таблицы библиотеки и FTS, поэтому Archive/Feed не имеют отдельного облачного пути чтения.

Решение конфликта проверяет ID снимка, generation и текущий shadow. Устаревший экран не перезапишет новую правку. `both` создаёт новую карточку; server tombstone прежнего UUID сохраняется.

`CloudMediaReferences` защищает фото текущих снимков/outbox/конфликтов от локального GC. `CloudReturnProjection` сохраняет единый серверный план без локального выбора и обратного экспорта серверных слотов. План, опередивший cursor записей, требует нового обмена и блокирует завершение отключения. Компактная техническая история сохраняет cooldown, последнюю дату по карточке, недавнюю суточную квоту и ordinal. Таблица `cloud_plan_slots` отмечает принадлежность серверу: отменённый слот удаляется из активного плана, даже если успел стать прошедшим офлайн.

Все объекты принадлежат каталогу подтверждённого аккаунта. Repository не знает URL, токенов, UIKit и lifecycle приложения.
