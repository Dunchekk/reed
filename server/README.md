# Сервер Reed

Один Fastify-сервис на TypeScript. Сервер отвечает за identity аккаунта и явно включаемую
облачную библиотеку. В локальном режиме тексты и фото остаются на iPhone. После
подключения облака записи, фото, правила и ограниченная история синхронизируются
между устройствами; черновики остаются локальными.

## Запуск

Из корня репозитория:

```sh
npm ci
docker --context colima-reed compose up -d --wait
cp server/.env.example server/.env
npm run db:migrate --workspace server
npm run dev --workspace server
```

Для Docker Engine без Colima убрать `--context colima-reed`. База доступна только
на `127.0.0.1:55432`; её содержимое хранится в отдельном volume `reed_reed_postgres`.
Команды очистки volume не являются частью обычного запуска.

## Границы

- `src/app.ts` создаёт приложение без открытого порта; удобно для HTTP-тестов.
- `src/index.ts` собирает зависимости, запускает listener и закрывает ресурсы.
- `src/auth/provider.ts` описывает узкий контракт подтверждения и сессии.
- `src/auth/routes.ts` валидирует вход и ограничивает частоту HTTP-запросов.
- `src/accounts` сопоставляет подтверждённый subject провайдера с Reed UUID.
- `src/database` выполняет SQL migrations в транзакции под advisory lock.
- `migrations` содержит неизменяемую историю схемы. Изменение уже применённого
  файла обнаруживается по checksum; изменение схемы оформляется новым файлом.

## Режимы входа

`AUTH_PROVIDER=development` принимает только синтетические номера
`+70000000000`…`+70000000099`. После запроса код — `123456`. Срок кода — пять
минут, повторная отправка — через минуту, пять попыток проверки. Сессии хранятся
в памяти, а аккаунты — в PostgreSQL. Перезапуск dev-сервера требует повторного
входа для серверных операций и не удаляет локальную библиотеку iPhone.

Production отказывается запускаться с development provider. Настоящий адаптер
использует `AUTH_PROVIDER=supabase`, `SUPABASE_URL` и publishable key. Настроить
Phone Auth и SMS provider необходимо отдельно. Проверки реальной доставки +7
пока нет. При отказе провайдера тестовый вход не включается автоматически.

Секреты, тела запросов и токены не логируются. Провайдер вызывается без общего
состояния пользовательской сессии. Внешние обращения ограничены timeout.
Rate limit локален одному серверному процессу; перед горизонтальным масштабированием
потребуется общее хранилище лимитов и явная настройка trusted proxy.

## Проверки

```sh
TEST_DATABASE_URL=postgres://reed_dev:reed_local_only@127.0.0.1:55432/reed_dev make server-check
```

Команда выполняет строгий typecheck, тесты и JS-сборку. Node запускает тестовый
TypeScript через встроенное удаление типов; это не заменяет `tsc --noEmit`.
Контракты API: [вход](../contracts/auth.md), [облако](../contracts/cloud.md).
Сквозная проверка на Mac: `TEST_DATABASE_URL=... scripts/cloud-e2e.sh`.

## Контакты и удаление

Смена номера, резервная почта и удаление реализованы через отдельный lifecycle-порт. Подробности и настройка почтовых шаблонов: [src/accounts/README.md](src/accounts/README.md). Примените новую миграцию перед запуском. Реальный провайдер и production-развёртывание в этом этапе не подключаются.

## Облачные модули

- [cloud](src/cloud/README.md): optimistic concurrency, journal/cursor, фото, очистка и лимиты.
- [returns](src/returns/README.md): правила без инфраструктурных зависимостей, проекция и общий сохранённый план.
- [notifications](src/notifications/README.md): APNs-адаптер и журнал отправок.

Миграции 003–006 обязательны. Для локальной разработки приватные фото находятся в `.local/cloud-objects` относительно рабочей папки server. В production нужен абсолютный `CLOUD_STORAGE_PATH` на постоянном закрытом диске; PostgreSQL и этот каталог должны входить в согласованную инфраструктурную резервную копию. Публичных URL фото нет. Этот адаптер рассчитан на один узел с диском; для нескольких узлов нужен общий ObjectStore.
