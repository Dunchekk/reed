# Аккаунт и жизненный цикл

HTTP только валидирует запросы и связывает порты. `AccountLifecycleProvider` отвечает за подтверждение контактов и удаление внешней identity. `AccountLifecycleRepository` хранит ожидаемое изменение контакта и устойчивую очередь удаления. UUID Reed привязан к паре provider/subject, а не к телефону; смена номера и вход через резервную почту сохраняют библиотеку.

Сначала пользователь подтверждает резервный email кодом. Восстановление — только через эту почту, `create_user: false`. Без заранее подтверждённой почты обхода входа нет. Почта не переносит локальные файлы на другой телефон: для них нужна резервная копия.

`DELETE /v1/account` возвращает 202 после блокировки аккаунта и удаления телефона/почты в PostgreSQL. Каждые 30 секунд worker повторяет удаление у провайдера, в том числе после перезапуска. Минимальная tombstone (UUID/provider/subject/status) остаётся, чтобы параллельный вход со старым токеном не пересоздал удаляемый аккаунт. Внешняя identity удаляется окончательно; это не мягкое удаление.

В development identities тоже находятся в PostgreSQL, поэтому смена контактов переживает перезапуск сервера; сессии и OTP остаются временными. Только +70000000000…99, адреса @example.test, код 123456. Этот адаптер запрещён в production.

## Supabase: подготовленная интеграция

Нужны SMS-провайдер, SMTP и шаблоны писем с шестизначным `{{ .Token }}`; реальная доставка в этом этапе не подключалась. Secure email change может потребовать оба кода (со старой и новой почты): ответ `confirmed: false` означает, что нужно второе подтверждение. `SUPABASE_SERVICE_ROLE_KEY` нужен только серверу для удаления, никогда не передаётся iOS. Без него capability удаления выключена.

Проверено по [updateUser](https://supabase.com/docs/reference/javascript/auth-updateuser), [verifyOtp](https://supabase.com/docs/reference/javascript/auth-verifyotp), [admin deleteUser](https://supabase.com/docs/reference/javascript/auth-admin-deleteuser). Живой провайдер перед бета-релизом требует отдельной проверки доставки и secure email change.
