# Облачные уведомления

`CloudPushWorker` продлевает общий план каждые 30 секунд, даже если приложение закрыто. Только основное, готовое после синхронизации, активное устройство с APNs-токеном может получать push. Выход при наличии сети приостанавливает устройство, новый успешный вход возобновляет регистрацию.

Журнал фиксирует попытку **до** сетевого запроса. `accepted` означает принятие APNs, а не гарантированный показ. После неопределённого ответа или падения между отправкой и записью результата попытка становится `unknown` и не повторяется: возможен пропуск, но нет слепого дублирования. Явные ответы 429/5xx допускают повтор через минуту в пределах 15 минут от слота. Прототип держит блокировку аккаунта на время ограниченного десятью секундами запроса, чтобы смена основного устройства и отзыв доступа не пересекались с отправкой.

В push нет цитаты, источника или фото. При выходе без сети сервер узнает о нём позже; уже принятый APNs push отозвать нельзя. Открытие карточки проверяет текущий аккаунт в приложении.

Адаптер `APNsProvider` заменяемый; тесты используют локальный fake. Для реальной доставки нужны `APNS_KEY_PATH` (закрытый P-256 .p8 вне репозитория), `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_TOPIC`, `APNS_SANDBOX=true|false` и подписанное приложение с Push Notifications capability. Без этих переменных сервер строит план и явно сообщает, что доставка недоступна. Никакие ключи или токены не логируются.

Контракт проверен по [запросам APNs](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns), [авторизации ES256](https://developer.apple.com/documentation/usernotifications/establishing-a-token-based-connection-to-apns) и [Node HTTP/2](https://nodejs.org/api/http2.html). Настоящая доставка на iPhone в этой среде не проверена.
