# Серверные тесты

Используем встроенный `node:test` и `assert`. HTTP-сценарии вызывают Fastify
через `inject`, поэтому не требуют порта. Провайдер SMS подменяется на границе
HTTP; настоящие SMS никогда не отправляются тестами.

- `app.test.ts`: health и запрет dev-входа в production.
- `development-auth.test.ts`: срок кода, повторная отправка, попытки, одноразовость,
  rotation и отзыв токенов. Время передаётся явно, ожиданий по таймеру нет.
- `supabase-auth.test.ts`: перевод внешнего контракта и безопасные ошибки.
- `auth-routes.test.ts`: вход через API, проверка bearer, refresh, logout и rate limit.
- `database.test.ts`: настоящая PostgreSQL, повторяемость миграций, стабильные
  UUID. Тестовые аккаунты создаются внутри откатываемой транзакции.

Без `TEST_DATABASE_URL` PostgreSQL-тест пропускается: такой прогон не считается
полной проверкой. В CI переменная задана и запускается настоящий PostgreSQL.
Не направлять её на production или пользовательскую базу.

Новые тесты должны проверять наблюдаемое поведение. Не дублируем каждую функцию
отдельным mock-тестом, не добавляем snapshots большого JSON без причины.


`account-lifecycle.test.ts` проходит через HTTP и настоящую PostgreSQL: подтверждение контактов, вход после перезапуска dev-провайдера, восстановление той же identity, блокировка pending deletion, повтор worker и удаление личных полей. Всё откатывается транзакцией. Supabase-тесты проверяют запрет чужой identity, серверные admin-credentials, повторный 404 и одинаковый ответ для неизвестной резервной почты.
